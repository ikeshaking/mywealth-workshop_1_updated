1 · The big picture

The tool turns a stack of dropped documents into a compliant Statement of Advice. The whole design rests on one idea: a single strategy engine driven by a maintainable word bank, where advice‑request keywords decide which tailored wording appears alongside the standard templated wording.

Inputs

What you drop in

  • Fact‑find / Projector JSON — client data + projected figures.
  • Advice request (blueprint) — the strategy & product recommendations, in keywords.
  • Supporting docs — CARE doc, WealthSolver, Risk Researcher, insurer quotes (recommended / alternative / commission).
Output

What comes out

  • A live preview and a Word (.docx) SOA.
  • Summary‑Strategies, Summary‑Outcomes, per‑strategy Advice sections, product & replacement tables, fees, disclosures, annexures.
The two architectural moves

1 · Generalise the debt‑module engine

Debt already works this way: a keyword in the advice request triggers a module that syncs three places at once (Summary‑Strategies + Summary‑Outcomes + the Advice section). Every other strategy area (property, investment, super, insurance, cashflow) gets the same treatment. See the Module engine tab to test it live.

2 · Externalise the word bank

Move tailored wording out of the code into an editable word‑bank file so paraplanners maintain it, it's versionable, and it drives both preview and Word.

Fact‑find / Projector JSON. importProjectorJSON() reads disc_* (people, assets, super, home/loan), calc_*/wc_* (projections), fn_* (fees), and builds F.superAccounts, current situation, goals, allocations. Client type from disc_client_type.
Advice Request. v143ApplyAdviceRequest() recognises which strategies are scoped in (section headings + keywords), activates the matching blocks, sets the risk profile, fees, platform, and triggers the keyword modules (currently debt only).
Supporting docs. CARE doc → recommended investment option + fees; WealthSolver → comparative platform costs; Risk Researcher → insurance comparison; ClearView/NEOS/insurer quotes → cover + premiums; commission report → disclosure %.
Smart‑drop classifier. v145ClassifyText() reads the file text and routes it: json · advicereq · care · wealthsolver · rr · clearview · neos · quote · commission. Each goes to its importer.
Importers. Each writes into the shared state: e.g. v48ImportCareDoc, v54ImportWealthSolver, parseAndApplyRR, v141ImportClearView/v141ImportNeos, parseAndApplyCommission.
State model. F holds all data (people, accounts, figures, flags); B holds each block's editable content (recommendation / why / risks / alternatives). Everything renders from here, so imports in any order converge.
Strategy engine + word bank. Today: DEBT_MODULES + v192MatchDebtModules → v194BuildDebtWording. Plan: a generic v200 engine + an external word bank so every area works the same way. Handles figure injection ({amt}, loan limits) and scope gating (gearing on/off).
Live preview. previewStrat() + section renderers build HTML that mirrors the Word layout.
Word export. generateSOA() builds the .docx with docx.js; seg() renders each strategy section's recommendation / why / risks / alternatives.

4 · The module engine — test it live

This is the heart of the tool. A module is keyword‑triggered tailored wording. Type advice‑request‑style text below (or click an example) and watch which modules fire — using the tool's actual debt regexes. This is how a reviewer can verify the trigger logic without reading code.

Module schema (what the word bank stores)

{
  id, area,                    // 'debt' | 'property' | 'invest' | 'super' | 'insurance' | …
  triggers: [/regex/, …],      // advice-request keywords / synonyms
  gate,                        // scope condition (e.g. gearing only if gearing scoped)
  strat, outcome,              // Summary-Strategies + Summary-Outcomes lines
  why[], risk[], alt[],        // Advice-section bullets (auto-selected)
  figures: [{token,extract}],  // {amt}, {limit}, {feeDiff} pulled from request / JSON
  needs: ['table:loanLimit'],  // tables / calcs this module requires
  variantOf                    // product/platform variant (Vanguard vs CARE, etc.)
}

The same shape covers every scenario you named — inspecie transfer, sell‑to‑buy, upgrade home, convert home → investment property, inheritance → pay down loan — they're just more rows in the word bank.

Three‑way sync + gating (already proven for debt)

sync
  • module strat → Summary‑Strategies
  • module outcome → Summary‑Outcomes
  • module why/risk/alt → Advice section
gate
  • gearing wording only if a gearing strategy is scoped
  • IP‑deposit wording only if an equity‑funded purchase is scoped
  • standard "always‑on" wording is appended regardless

ROA Paraplanner — Standard Operating Procedure

My Wealth Solutions · Tool build v7.b_20 · SOP version 1.0 · July 2026

Part A — Common workflow (every ROA type)

A1. Opening the tool and staying on the same version

  • The tool is a single HTML file. Save it locally and open it in a normal browser tab (Chrome/Edge recommended). Do not run it from a preview pane inside another app — file-picker dialogs will not open there.
  • The build version shows in the top bar (e.g. v7.b_20). Everyone on the team must run the SAME build — if two people's drafts differ, compare this stamp first.
  • The tool needs an internet connection the first time it loads (fonts and the Word/PDF readers load from the internet). Scanned/image documents also need a connection for OCR.

A2. Starting, saving and recovering work

  • Start a new ROA with the red ♻ Reset button (top right). It always asks before clearing anything.
  • Your work auto-saves to the browser moments after every change. If the tab is closed, reopening the tool offers the draft back — choose Restore to continue or Cancel to start fresh.
  • Closing the tab with unsaved work triggers a browser warning.
  • Undo / redo: ↶ ↷ buttons in the top bar, or Ctrl/⌘+Z and Ctrl+Y (⌘+Shift+Z). Typing inside a field keeps the normal text-editing undo.
  • To keep a permanent copy: 💾 Save copy (a full HTML file with your work embedded — reopen it anywhere), or Save (JSON) on the Preview page (a small data file you can Load later).

A3. Step 1 — Scenarios page

  1. Choose the document type tab: ROA Generator (this SOP), Strategy Paper, or NAA.
  2. Tick every scenario the advice covers. Scenarios are grouped by category: Superannuation, Pension, Investment, Insurance, Cashflow & Debt. Use the search box (e.g. "rollover", "income protection") to find one quickly.
  3. Selected scenarios appear as chips at the top — use the ◀ ▶ arrows to set their order (this drives the order of wording in the document) and × to remove one.
  4. Press 2 · Build in the top bar (or the Start button) once everything is selected. You can return and add/remove scenarios at any time — the builder keeps your work.
The scenario selection decides which sections, tables and wording appear everywhere else. If a table you expect is missing (e.g. no insurance tables), the right scenario has not been selected.

A4. Step 2 — Builder: wizard and all-sections views

  • The builder opens in the Wizard view: steps listed down the left, one section at a time in the middle, and a live preview of the actual document on the right.
  • Step ticks: green ✓ = complete, orange ! = something needs attention (hover for the reason; the yellow banner on the step says exactly what, e.g. "Client 2 name is blank"), number = not started, – = hidden from the output.
  • Back / Next buttons sit at the bottom; the last step finishes into the Preview page. Click any step in the left list to jump straight to it.
  • The live preview updates as you type and scrolls to the part of the document the current step edits. Hide it with 🙈 Hide preview (left panel) or ✕ on the panel; ⛶ Full opens the full-size preview page.
  • Prefer one long page? ⊞ All sections (top right of the builder) shows every section stacked with a sidebar; 🧭 Wizard view switches back. The choice is remembered on your device.
  • Any section with an ✕ button can be excluded from the output (it stays editable and can be re-included).

A5. Wizard steps common to every ROA

Step — Client & Adviser Details

  • Client type: Single, Joint (Couple), Individual + Entity, or Joint + Entity. Joint enables Client 2 fields and drives joint wording ("R & J, we recommend…").
  • Enter the client name(s) FIRST, before importing documents — the importers use the names to route and filter (see A7).
  • Client marginal tax rate (optional): used only to estimate the after-tax cost of personally-funded IP.
  • Adviser: start typing to search the adviser list (set up in Admin). Phone/email/address fill from the roster.

Step — Type of ROA & Prior Advice

  • ROA date: drives the cover page and the export file name.
  • Each selected scenario gets a toggle: Additional Advice vs Amendment of SoA — set per scenario; the cover-page table lists one row per scenario.
  • Prior advice documents (type + date) are listed here; they print in Section 1. Use the Exclude from output button if Section 1 should not print.

Step — What You Want To Achieve (Section 2)

  • The objectives narrative is generated from the selected scenarios, with connectors between them. Edit it freely — your edits stick (see A6). ↻ Regenerate rebuilds it from scratch.
  • Replace any [Amount]-style placeholders with the real figures — the step tick warns while placeholders remain.

Step — Custom Sections, Fees, Acknowledgement

  • Custom sections: add free-form sections (text / bullets / two-column tables) that print after the projection.
  • Fees: default is "no changes to our ongoing service fees". If fees change (e.g. insurance commissions), switch the toggle and complete the commission details.
  • Acknowledgement: standard signing section — normally untouched.

A6. How the generated wording behaves (important)

  • Recommendations, objectives, benefits and risks are GENERATED from the scenario library, then become yours to edit.
  • Edits are safe: changing a client name, adding a scenario or importing a document no longer wipes your edited wording — only buckets you have NOT touched regenerate.
  • The ↻ Regenerate buttons are the explicit way to throw away edits in that area and rebuild from the library.
  • Firm-wide default wording is edited in ⚙ Admin (see Part E) — not per ROA.

A7. Smart Import — one drop zone for every document

  • Where: the dashed "Smart import" zone in Section 3 (My Advice). Drop one or many files, or click Choose files…
  • Each file is identified automatically and routed to the right importer. You are shown the routing and asked to confirm before anything is applied.
  • Accepted: CARE/Hub24 rebalance doc (.docx), WealthSolver comparison (.docx), CDM benefits report, insurance schedules, insurer quotes and alteration quotes (PDF), prior SOA/ROA (.docx), screenshots of the firm's cover table (PNG/JPG — OCR), saved ROA .json, saved tool .html.
  • Client filtering: on a single-client ROA, a joint document (CARE doc, CDM report, quote) offers to import ONLY that client's accounts/covers — matched by name or initial ("R Super" matches Robert). Joint and entity accounts always stay.
  • Partners: importing a second quote whose life insured is a different person APPENDS under the existing rows automatically — drop both partners' quotes one after the other.
  • Every import ends with a confirmation summary; nothing is applied silently, and every value stays editable afterwards.

A8. Preview and export

  • Preview (step 3) shows the document exactly as it will print. Use ← Back to Builder to keep editing.
  • 📄 Export to Word produces the .docx, named to the firm convention automatically (dates AEST, from the ROA date):
YYMMDD;Surname;Initials;Type-ROA;DDMMYY — e.g. 260713;Sharp;E;Insurance-ROA;130726 · 260713;Smith;A&C;Super&Inv-ROA;130726 · 260713;Hans&Barker;K&T;Inv-ROA;130726 (couples with different surnames join both). The Type part is built from the advice areas: Super, Pension, Inv, Insurance, Cashflow.
  • 💾 Save (JSON) stores the ROA data to reopen later with 📂 Load (JSON).

Part B — Superannuation & Investment ROAs (incl. Pension)

B1. When to use, and the scenario options

  • Use these for portfolio advice: contributions (concessional / non-concessional / spouse split / downsizer / carry-forward), rollovers and new accounts, portfolio rebalances, investment-menu switches, withdrawals and pension commencement/commutation, reserves top-ups, DCA plans, and similar.
  • Pick one scenario per piece of advice. A combined ROA (e.g. salary sacrifice + NCC + rebalance) is normal — each becomes its own recommendation bullet and its wording merges into the right category block.

B2. Building the portfolio tables

Option 1 — CARE / Hub24 clients: 📥 Import CARE doc

  1. In Section 3, press 📥 Import CARE doc (only visible on super/investment/pension ROAs) and choose the CARE rebalance document as a WORD (.docx) file. A PDF export loses the table structure — if you only have a PDF, export the Word version from CARE.
  2. The importer reads every account ("Rebalance – J Super", "CARE Portfolio Fact Sheet" layouts) and shows a summary: accounts found, owners, risk profiles, totals, trade lines.
  3. On confirm it creates ONE portfolio per account with the allocation table, variation table and buy/sell trades pre-filled. Super accounts sort before investment accounts automatically.
  • Joint docs on a single ROA: it offers to import only the matching client's accounts (joint/entity accounts stay). Two personal owners on a blank joint ROA pre-fill the client names.

Option 2 — Non-CARE clients: 📥 Import WealthSolver

  1. Press 📥 Import WealthSolver and choose the WealthSolver comparison (.docx).
  2. The importer builds the portfolio from the recommended platform column of the Plans table (holdings + total) and fills the fee cells from the Fees table's Gross Ongoing Costs, showing the current-vs-recommended cost change.

Option 3 — Manual

  • + Add another portfolio creates an empty portfolio. Set the label, platform, total, and the allocation rows; choose the asset set (CARE or Vanguard) to pre-fill standard fund rows.
  • Portfolio extras: an optional Ongoing Regular Investment row and the Dollar Cost Average/Lump Sum band (standard wordings available: lump sum, staged DCA, super rollover).

B3. How Section 3 flows (and where benefits & risks go)

  • The document always prints: ALL super tables first (both partners on a couple), then ONE combined Superannuation benefits & risks block; then the investment table(s) and ONE Investment benefits & risks block; Pension sits between Super and Investment.
  • The builder mirrors this exactly: category band → each portfolio's strategy block (1. We Recommend, 2. Allocation Table & Trades, 3. Variation Table) → one "Benefits & Risks" block per category.
  • Category recommendations (e.g. contribution advice bullets) print after the tables and before the benefits — edit them in the category block's step 1.
  • If a table exists with no scenario wording (e.g. a CARE import created an investment portfolio but no investment scenario was picked), the category's rebalance benefits & risks are auto-seeded so nothing prints bare. Edit or delete as needed.
  • Per-portfolio recommendations (rebalance bullets from the trades) print above each portfolio's own table.

B4. Before exporting — checks

  • Every portfolio has amounts in its allocation table (the wizard flags empty ones).
  • Variation table percentages read correctly (the importer fills them from the CARE doc; manual portfolios need them typed).
  • Risk profile set (Client details step) when the advice references it.
  • Objectives and recommendation bullets have no [placeholders] left.

Part C — Insurance ROAs

C1. Insurance scenario types and what each produces

  • Increase / decrease / cancel cover, waiting-period and benefit-period changes, premium-structure changes → Current Cover + Recommended Cover tables.
  • Revised terms after underwriting (retain & alter, transfer to Hub24, insurer switch, accident-only exclusions, employer-paid variants) → Original Recommendations + Recommended (Altered) Cover, plus the Option 2 (Alternative) — proceed as originally recommended — table with NOTES.
  • Two-option comparisons → Option 1 and Option 2 tables with summary bullets.
  • New cover / key person / child cover → Recommended Cover table.
  • Death benefit nominations (BDBN) → nominee table (no cover tables).
On a two-option ROA the benefits & risks always print under OPTION 1 (after its cover table), before the Option 2 table — the tool enforces this.

C2. The insurance tables

  • Tables appear in the Insurance Cover section based on the selected scenarios: Current, Recommended, Original, Altered, Alternative, Option 1, Option 2.
  • Each row: provider (grouped into coloured provider bands), life insured, owner (Super / Flexi-Linked Super / person), status, benefit amount, premium structure, monthly premium.
  • Statuses you will see after imports: In Force (current cover), Recommend, Retain, Retain & Alter, Reduce, Increase, Cancel, New.
  • Linked Life + TPD rows share ONE combined premium — the premium cell merges across the pair (untick the share checkbox to split).
  • Premium cell conventions, printed as separate lines: "$83 pm (before tax)", "($71 from super and $13 from personal cashflow)", "$73 pm (after tax)". IP rows also carry the Super Contribution Option and "(4 weeks wait, until Age 65)" under the benefit.
  • ⇄ Mirror copies a whole table (e.g. Current → Recommended) so you only edit what changes.
  • Benefits & Risks for insurance are edited in the Insurance Cover section, after the tables — exactly where they print.

C3. Importing insurance documents (fastest way to fill tables)

  • Use Smart Import, the 📥 Import / drop document button on any table, or drag a file onto a table's card.

Existing cover (fills Current Cover, status In Force)

  • CDM Benefits Report · CDM/adviser INSURANCE SCHEDULE PDFs · prior SOA/ROA cover tables · screenshots of the firm's Insurance Products table (OCR).

New-business quotes (fill Recommended Cover)

  • NEOS · ClearView ClearChoice · Zurich (Active and Wealth Protection) · OnePath OneCare · MetLife Protect. Each produces firm-style rows: flexi-linked Life+TPD combined premium with the super/personal split, IP with SCO, waiting and benefit periods, TPD definition.

Alteration / in-force quotes (fill BOTH tables in one drop via Smart Import)

  • AIA (Current Plan vs New Quotation) · TAL-style Policy Alteration Illustrations · ClearView LifeSolutions alteration quotes and Amended Terms letters · Zurich alteration quotations · NEOS in-force quote emails · MetLife alteration quote emails.
  • The existing side lands in Current Cover (In Force); the proposed side lands in Recommended/Altered with the change flagged per row: Retain & Alter, Reduce, Cancel (cover disappearing), New (cover added). A reduction can not slip through unnoticed.
  • Documents holding multiple quote options (AIA quotes, MetLife Quote 1/2, ClearView alternative bundles, TAL multi-quote illustrations) ask which option to apply.
  • A prior SOA (.docx) imports BOTH clients' recommended tables — routed to Original Recommendations on a revised-terms ROA, otherwise Current Cover.
  • Unknown insurer or layout? The generic table/keyword readers still recover cover types, amounts and premiums — review the grid afterwards. Send a sample to have an exact reader added.

C4. Two-option (revised terms) ROAs — specifics

  • Order printed: Original Recommendations → Recommended (Altered) Cover → benefits & risks (Option 1) → Superannuation Recommendation (when retaining external super) → Option 2 (Alternative) table → NOTES.
  • The Option 2 intro and NOTES bullets are editable in the Insurance section; the premium-increase and underinsurance notes default in.
  • Retain-external-super variants also produce a super allocation table — import it from the prior ROA/SOA or fill manually.

C5. Commission / fees

  • If commissions change, switch Fees to "changed" and enter Implementation and Renewal amounts — they print as the remuneration table in the Fees section.

C6. Before exporting — checks

  • Every table the scenarios need has content (the wizard flags empty ones by name).
  • Life insured / owner set on each row (imports fill them; manual rows need them).
  • Statuses reflect the advice (especially Cancel rows on reductions).
  • Premium split notes read correctly on flexi-linked covers.

Part D — Other categories

D1. Cashflow & Debt scenarios

  • General (non-portfolio) strategies — offset accounts, budgeting tools, debt recycling and similar. They produce recommendation bullets + benefits & risks in their own block after the portfolio categories; no tables.

D2. Death Benefit Nominations

  • Select "Super — Death Benefit Nomination (BDBN)" (Superannuation category). It adds a nomination section to the builder: nomination type, nominee table (name / relationship / allocation %) and note, plus the standard BDBN recommendation, benefits and risks wording.

Part E — Admin panel (back office)

  • ⚙ Admin (top bar) — soft password lock. Manage the adviser roster, licensee details and the default suggested wording per scenario.
  • Wording changed in Admin becomes the default for FUTURE generations (new ROAs / Regenerate); it does not rewrite documents in progress.
  • Export settings file (new HTML) bakes the roster + wording into a fresh copy of the tool for the whole team — this is how defaults are distributed. Export/Import settings (JSON) moves settings between copies.

Part F — Troubleshooting

  • "Button doesn't open a file dialog" → you are in a preview pane; save the HTML and open it in a real browser tab.
  • "CARE import says use the Word version" → the CARE doc must be .docx; PDF exports lose the table structure.
  • "No insurance cover lines were found" → check the file is text-based (not a scan); Word versions read best; screenshots go through OCR (needs internet). If the layout is new, send the file for a parser to be added.
  • Import filled the wrong table → every import confirms its target first; Cancel and use the 📥 button on the specific table instead.
  • An import replaced rows you wanted to keep → Ctrl/⌘+Z undoes it; on re-import choose UPDATE instead of REPLACE.
  • Wording reverted unexpectedly → only ↻ Regenerate discards edits; plain field changes never do. Check whether someone pressed Regenerate.
  • Work disappeared after closing the tab → reopen the tool; the auto-saved draft is offered back. For permanent copies use 💾 Save copy or Save (JSON).
  • Different output on a colleague's machine → compare the version stamps in the top bar; everyone must run the same build.

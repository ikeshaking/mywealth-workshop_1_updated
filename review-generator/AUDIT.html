Wealth Review Generator — Audit Report

Artifact: review-generator/Review_Generator.html · Single self-contained file (~505 KB) · Client-side only

Scope of this audit: architecture, feature coverage, data flows, checklist completeness vs the original firm checklist, Word-output fidelity vs the MWS FINAL template, security/privacy posture, known limitations, and verification performed.

1. Overview & architecture

The tool is a single HTML file that runs entirely in the browser — no server, no backend, no database. All client data stays on the machine; nothing is transmitted anywhere. It is built around one in-memory state object (S) and pure render functions; there is no framework.

  • ~134 functions, one global state object S, 14 checklist sections, 182 checklist prompts.
  • Four-stage workflow (top tabs): ① Pre-Review Checklist → ② Generate Wealth Doc → ③ Review Meeting → ④ Post Review.
  • Rendering model: structural changes re-render; free-text inputs mutate state without re-rendering (preserves focus).

2. Feature-by-feature audit

① Pre-Review Checklist

  • Data-driven schema (CHECKLIST_SCHEMA): sections have appliesWhen (shown only if the client holds that account type); items are typed (yes/no, currency, date, text, select), optionally perClient, with inline followUps, routeNote, todo, and computed panels.
  • Client 1 / Client 2 aware; captures Client 1, Client 2 and Joint CRP.
  • 14 sections: Scope, General, Compliance, Retail Super, Held Super, SMSF (full strategy checklist), MCMA, Investment/DR, Investment Bonds, Property, Loans, Insurance, Held Insurance, Adviser Fees.
  • Computed rules/flags: SG expected-vs-actual (annualised) shortfall, held-super partial-rollover $6k/$10k threshold, adviser-fee SOA/OSA/actual comparison.
  • Routing on Apply: action answers → to-do items (de-duplicated); data answers → the matching wealth-doc section; CRP → meta.crp + adviser comments.
  • Presentation: hybrid — jump-to section sidebar with completion counts + Back/Next; full-width tab.

② Generate Wealth Doc

  • Wired parsers: HUB24, BT Panorama, Macquarie (auto-detect per PDF); prior review (.docx); PTW (.xlsm); CARE rebalance (.xlsx).
  • Stub slots (await a sample): Review Data Snapshot, insurance CDM/renewal, property valuations, Netwealth/CFS/Mercer — accept files with a clear "sample needed" state.
  • Uploaded reports show as removable chips; per-page and global Reset.
  • Licensee/practice dropdown (seeded with GPS Wealth) prefills compliance details.
  • Standard review to-do template seeded into every new review.

③ Review Meeting

  • Dashboard (net position, open actions, tracked changes, rebalance, rating) beside the live preview.
  • Live edit — a baseline is locked on entry; only in-meeting changes are tracked and feed the file note & ROA.
  • Hide/unhide preview toggle.

④ Post Review

  • Changes Made (diff vs baseline), File Note (After Review Summary), ROA (No-change / Rebalance) — each shown as a live Word-style document preview beside the editable text.
  • Copy review summary + to-dos handoff (for the Donna email / bcc Xeppo).

Word generation — fidelity vs the MWS FINAL template

  • Landscape A4, embedded cover/back artwork, Nunito body + ABC Arizona Flare headings, brand blue #0C6AE1, teal #E3F2F4, navy bands #0C2E3F.
  • Front-matter AR/compliance block (Adviser + Insurance Specialist as Authorised Reps, CAR 441414 of GPS Wealth, AFSL 254 544, ABN 66 153 751 832) + static "What does this document cover?" panel.
  • Footer "PAGE n / WEALTH REVIEW"; combined Foundations + Estate; template rating palette.
  • The live on-screen preview now mirrors this template page-for-page.

4. Security & privacy posture

  • All processing is client-side. No network calls carry client data; documents are read in-browser only. No AI/LLM and no third-party data egress — chosen for client-financial-data privacy.
  • Saved drafts are plain .json files the user controls; transient keys are excluded from saved output.
  • No secrets, tokens or credentials are stored in the file.

5. Known limitations & risks

  1. Report parsers not yet wired for several formats (Review Data Snapshot, contributions, insurance CDM, MCMA statement, performance report, Cotality) — stub slots pending one real sample each; figures entered/confirmed manually until then.
  2. Word/PDF export depends on CDN libraries — unavailable in a locked-down/offline environment until they load.
  3. SG reconciliation annualises FY-to-date on a whole-month basis with a single SG rate — treat the flag as a prompt, not a precise figure.
  4. Legacy .xlsx checklist upload routes actions/notes but does not repopulate the new questionnaire (format predates the schema).
  5. Cover/back artwork uses the compressed JPEG (visually identical to the template PNG) to keep the single-file size reasonable.

6. Verification performed

  • Headless browser (Chromium/Playwright): every tab and section rendered; checklist exercised for 1 and 2 clients across all account types; conditional sections, per-client fields, follow-ups, computed panels and routing verified; 0 console errors (only expected offline-CDN network errors).
  • JSON save/load round-trips the checklist model.
  • docx.js constructs (Table-in-Footer, cover two-column shaded table, 5-column Foundations) packed successfully against the real docx package.
  • Syntax validated with node --check after each change.

7. Recommendations / roadmap

  • Wire the deterministic parsers as real samples are supplied (unlocks full auto-prefill).
  • Optionally add a bring-your-own-key AI-assist layer (off by default) for free-form SOA reading, with a compliance review of data handling.
  • Add the firm's additional licensee/practice entities and advisers to the config lists.
  • Consider checking in the Playwright drivers as a lightweight automated test harness.
